# muw-api

基于 [QuantumNous/new-api](https://github.com/QuantumNous/new-api) 的个人二次开发分支（fork）。

本 fork 保留上游 new-api 的全部能力（统一网关、40+ 上游提供商、用户/计费/限流、管理后台），在此之上针对自用场景做了大量增强与精简。所有上游品牌、版权与归属归 new-api / QuantumNous 所有。

## 主要增强

### 订阅系统重设计

- **独立额度计数器**：总额度 + 周期重置额度 + 自然周限额 + 自然月限额，四套额度各自独立累计、各自按窗口推进，互不干扰（替代上游靠快照差值推演的多处 bug 来源）
- **套餐档位 + 互斥组**：新增 `Priority` 档位，同互斥组套餐不能共存；余额显式升降配，升级/降级/平级方向按档位自动判定
- **消费优先级（Use First）**、**用户组升降级**（升级/到期降级）、**自动续费 + 到期提醒**
- **全局同时持有套餐数量上限**；自动续费 / 消费优先级 / 互斥组 / 组升降级均做成可开可关的开关
- 订阅额度用户组白名单（空 = 全部用户放行），余额 / epay 双支付

### 额度池

- 单一额度池 + 签到打卡，分周期统计；按规则领取额度，剩余不足提前禁用领取入口

### 模型健康监控

- Uptime Kuma 风格色块面板，普通用户可查看模型健康、管理员看渠道详情
- 记录真实用户流量（带 source 标注），支持自动测试所有模型

### 限流体系

- **三组 IP 维度限流**（敏感操作 / 全局 API / 全局 Web）的开关、次数、时间窗口全部迁入设置页，**修改后热生效，无需重启**
- 订阅写操作、额度池签到/领取按**用户维度**限流，避免共享 per-IP 桶导致已登录用户被连坐踢下线
- relay 模型请求限流（按用户/分组配额）

### 认证与用户

- Passkey 免密登录、两步验证（2FA）、通用安全验证
- 自定义 OAuth 提供商（GitHub / Discord / OIDC / LinuxDO 统一路由 + 发现配置）
- OAuth 登录自动同步头像、支持上传自定义头像
- LinuxDO 信任等级自动分组 + 黑名单（Id/用户名匹配，注册与登录均拦截）
- 用户偏好策略支持管理员强开 / 禁止用户修改

### 模型与转发

- **视觉兜底**：非视觉模型自动将图片转为文字描述后转发
- 供应商（Vendors）管理与倍率同步（支持自定义上游 + sub2api 价格转换）
- 模型页 / 渠道页卡片视图

### 运维与基建

- **schema 版本化迁移**：已最新库跳过 AutoMigrate，启动更快更稳
- **SQLite 加固**：启用 WAL + `_txlock=immediate`，修复并发「database is locked」类问题
- 支持 SQLite / MySQL / PostgreSQL 三库

## 精简项

- 移除 Stripe / Creem / Waffo 等第三方支付渠道与 io.net 模型部署，仅保留自用支付链路（余额 / epay）

## 构建与部署

本 fork 构建、部署方式与上游一致，详见上游 [README.md](./README.md)。
